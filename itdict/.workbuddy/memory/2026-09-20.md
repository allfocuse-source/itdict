**产出**：`程序员不可不知的英文词汇-字母排序表.md`（914 条，A–Z 共 24 个分组，每组一张 `| # | 英文词汇 | 中文释义 |` 表格 + 顶部条目数总表）。

**关键处理（原文数据质量问题较多）**：
- 分隔符为 `<br />`，需先按 `\xa0`、多空格归一化；标题行 `# ...` 需剔除。
- 大量「中英粘连」：`abstract baseclass`、`assignmentoperator`、`B2B integrationB2B`、`CHECK constraintsCHECK`、`XML MessageInterface (XMI) XML` 等，需用「长串→规范写法」字典按长度倒序替换。
- 括号截断导致的英文片段：`cookie (`、`getter (`、`dereferenceoperator (`，需按 `(` 切分后分别成行。
- 原文错别字：`Dlectronic`→Electronic、`Universary`→Universal、`squarebrakcet`→square bracket。
- 原文缺中文的条目（ADL、ODR、POD、POI、qualified name 等 22 条）已补译。
- 多义词 `cursor / field / snapshot / view` 各有「通用 / 数据库」两义，用 `(database)` 后缀区分避免去重误删。
- 文末「算法与数据结构」部分（约 82 条）原文只有中文，英文按原文补全。
- 首字母取「第一个拉丁字母」→ 处理 `A.I.`、`ASP.NET`、`XSLT` 等缩写正确归入 A / A / X。

**可复用要点**：处理这类「半结构化中英词表」时，稳妥流程是 ①先导出全部条目到临时文件肉眼普查 → ②用「英文片段以中文起点切分」得到两列 → ③对英文列跑粘连修复字典 → ④统一中文全角标点与括号配对 → ⑤去重与多义消歧 → ⑥按首字母分组排序输出。直接写正则硬拆极易漏项。

## 程序员必备的600个英语词汇.md → 字母排序表格

**任务**：同一目录下 `程序员必备的600个英语词汇.md` 做同样的字母排序表格。

**产出**：`程序员必备的600个英语词汇-字母排序表.md`（472 条，A–T 共 19 个分组）。

**与上一份的关键差异（数据形态更杂）**：
- 原文 497 个 `<br />` 片段，但并非 497 个词条——存在**跨片段续行**：片段以中文/`(`/`例`/`※`/`叁考` 开头时属于上一条的释义补充，需并入上一行（如 `class template partial specializations` + `类别模板偏特化 类模板部分特化`）。
- 每条通常有**两个译名**：繁体台湾译名 + 简体大陆译名，表格中文列统一为「台/港 · 大陆」双读法。
- 纯注释片段（`※ 最近我比较喜欢…`、`叁考 demarshal`、`址叁器, see pointer`）直接丢弃，不作为词条。
- 运算符类条目常把单词重复一次再跟括号，如 `arrow operator arrow(箭头)运算子`、`dot operator dot(句点)运算子`，需单独订正。
- 原文错字：`build-in`→built-in、`factor`→functor（实为 functor）、`square brakcet`→square bracket、`enemy 型别`→enum。
- 括号转换坑：**不能用 `(?<=[\u4e00-\u9fff])\)` 这类单边替换**，会把半角 `(中文)` 变成 `（中文）` 单边失配。正确做法是循环 `re.sub(r'\(([^()]*)\)', r'（\1）', z)` 先把成对括号整体转全角，再映射残留单括号，最后做配对补齐。
- 多义条目（`resolution` 决议 / 分辨率）用 `(dpi)` 等后缀区分，避免被去重合并。

**结论**：两份文件都已生成对应排序表，命名规则统一为「原名-字母排序表.md」。

## 程序员必学电脑计算机专业英语词汇1700词.md → 字母排序表格

**任务**：同目录第 3 份文件，同样按首字母排序输出表格。

**产出**：`程序员必学电脑计算机专业英语词汇1700词-字母排序表.md`（**1700 条**，A–Z 共 26 个分组，含 Y / Z）。

**数据形态（三份中最规整）**：
- 结构统一为「`单词` + `<br />` + 空格 + 词性释义」，条目之间以**空行**分隔，共 1824 个块。
- **原文存在重复词条**：119 个词各出现 2 次（switch 出现 3 次），且释义完全相同 → 去重后正好 **1700 条**，与文件名「1700词」吻合。这是三份文件里唯一的去重场景。
- 少数条目有多个 `<br />`（如 put / resume / table / row / freeze），表示同一词的多种词性，合并为一行释义即可。
- 英文列全部为**单个单词**（无短语），首字母分组最纯粹。
- 需处理 `\xa0`（不间断空格）、HTML 实体 `&amp;`、半角括号 `(中文）` 混搭、落单双引号等问题。

**括号/引号处理的最终稳妥写法**（踩过坑，值得复用）：
1. `re.sub(r'\(([^()（）]*）)', r'（\1', t)` —— 修半角 `(` + 全角 `）` 的混搭；
2. 循环 `re.sub(r'\(([^()]*)\)', r'（\1）', t)` —— 成对半角整体转全角；
3. 残留单括号直接字符映射，再按数量差补全；
4. 引号先 `re.sub(r'"([^"]*)"', r'「\1」', t)`，再用 `「([^「」]*)「` → `「\1」` 修「两个左引号」这种落单情况。
   教训：**不要用「就近插入括号」这类位置启发式**，会把 `＆(and 的符号）` 修坏。

**最终校验**：1700 条、0 重复、0 括号失衡、0 引号失配、0 HTML 实体残留。

**三份文件总览**：914 条（不可不知）+ 472 条（必备600）+ 1700 条（必学1700），命名规则统一为 `原名-字母排序表.md`，均放在源文件同目录。
